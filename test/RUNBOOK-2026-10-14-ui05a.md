## Facts the predictions depend on, read from the source at `e248dbc`

- **A fresh profile starts with the toggle OFF** and `hw:sync` alone in
  storage, state `paused`. The toggle is turned on before `probe` is saved, so
  that its rule registers.
- **The form writes a request entry with no `side` key**, a response entry
  with `side: "response"`, and a remove with `value: ""` (`readForm`). SET-4
  writes its fixtures in the same shape.
- **Chrome registers an appended request header's name in lowercase** (AR-23):
  `X-Forwarded-For` reads `x-forwarded-for` in the rule and on the card.
- **A profile whose domain is not granted is skipped** by the worker: its card
  reads `No rule registered for this profile` with no table, its domain chip is
  a **button** (clicking it asks for a grant; do not click it), and the footer
  names it in `Not registered: profile <id>`.
- **The table** (`renderReadbackTable`): a `caption` from `READBACK_CAPTION`,
  one `th` per column with `scope = "col"`, one row per registered entry in
  registered order (request entries, then response entries), cells `rb-type`,
  `rb-action`, `rb-header` (the name in a `div.rb-name`, at most 200 px, wrapping
  at any character), `rb-value` (`white-space: pre`, cut with an ellipsis).
- **A cut value** (`measureValueCell`): class `cut` and `tabindex="0"`, set when
  `scrollWidth > clientWidth`; a value that fits has neither. **The popover**
  (`showValuePopover`) opens on `mouseover` or `focusin` on a cut cell, takes
  the cell's `textContent`, its left at the table's left, below the cell when it
  fits; it closes on `mouseout` (unless the pointer went onto it), on `focusout`,
  on leaving it, and when the list scrolls. Hiding it does not clear its text.
- **Focus leaving the popup's window** (a click in DevTools) is expected to
  fire `focusout` on the focused element, which would close the popover, and
  focus coming back to fire `focusin` on it again: a property of the browser,
  not of this source, and not run in the container, where nothing takes focus
  away. So the popover's state is read by a recorder H installs, which notes
  every focus and every open and close as it happens, and no reading depends on
  the popover still being open when the console is used. Whether it closes is
  recorded (UV7).
- **With DevTools attached, the popup stays open behind the permission dialog**
  (the s5 sitting, UI04-3) and on Chrome 154 closing DevTools does not close the
  popup.
